# TradePilot 期货实施计划

制定日期：2026-09-19。状态：待实施。

## 1. 目标与范围

把 TradePilot 扩展为国内商品期货研究与交易辅助工具，逐步具备真实合约监控、风险测算、可信回测、实时模拟交易和受控实盘能力。

本计划采用以下初始假设，启动时确认即可：

- 面向个人使用，以国内商品期货为首期市场。
- 观察池先覆盖 3–5 个品种，按数据质量、流动性、账户权限和最小一手风险筛选。
- 优先验证 60 分钟趋势策略，使用已完成 K 线生成信号；若分钟数据质量或权限不满足要求，先交付日线版。
- 首期以监控、提醒和风险测算为交付目标，真实订单接入放在独立阶段。
- 暂缓高频交易、期权、跨市场套利、多用户资管和期货机器学习模型训练。

第一版用户流程：观察池 → 具体合约 → 信号依据 → 风险测算 → 提醒与复盘。

## 2. 当前基础与缺口

| 领域 | 当前基础 | 本计划需要补齐 |
| --- | --- | --- |
| 展示 | 已有期货观察池、资产分类和策略配置入口 | 稳定行情接入、交易状态、合约字段与期货信号语义 |
| 策略 | 已有 Donchian、ATR、均线等模块 | 多空持仓语义、明确的信号时点、统一的目标持仓输出 |
| 回测 | 已有撮合、成本、交易规则与样本外验证模块 | 合约乘数、保证金、多空、结算、换月和期货费用 |
| 风控 | 已有仓位、止损、止盈及回撤控制 | 空头风控、每手风险、保证金占用和组合限额 |
| 执行 | 已有历史回放纸面执行；实盘接口为占位 | 实时模拟、完整订单状态、幂等、对账与恢复 |
| 服务 | 已有 FastAPI、CLI、通知和持久化基础 | 期货运行状态、行情延迟与账户审计记录 |

现有默认交易规则和成本以 A 股为基础，包含 100 股一手、T+1、卖出印花税；不能直接用于期货绩效计算。现有纸面执行是历史回放，不等于实时模拟账户。

## 3. 排期与里程碑

按一名开发者持续投入估算，数据权限、接口接入和缺陷修复会影响工期。阶段按验收结果推进，日期不是实盘上线承诺。

| 阶段 | 参考排期 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| P0 范围与技术验证 | 第 1 周 | 数据源结论、合约样例、规则清单、接口设计 | 一个品种真实合约的数据与规则可核验 |
| P1 监控 MVP | 第 2–3 周 | 观察池、行情、信号、风险测算与飞书提醒 | 连续 5 个交易日运行记录完整，覆盖夜盘及休市 |
| P2 期货回测 | 第 4–7 周 | 期货账户与撮合模型、成本、结算、换月、样本外报告 | 固定案例逐笔账目核对通过，无已知前视偏差 |
| P3 实时模拟 | 第 8–9 周开发，随后观察至少 4–8 周 | 模拟订单、持仓、账户、对账与故障恢复 | 满足运行稳定性、交易样本和策略评估门槛 |
| P4 受控实盘 | P3 验收后单独排期 | 一个交易通道、小规模运行和运维手册 | 接口权限、风控、对账及故障演练全部通过 |

## 4. 分阶段任务

### P0：范围与技术验证（2026-09-19 完成，验证记录见 [futures-p0-verification.md](futures-p0-verification.md)）

- [x] 确定首批品种、主周期、是否参与夜盘、模拟资金规模和账户权限。（rb/hc/cu/i/m，60 分钟，参与夜盘，模拟资金 20 万/单笔 1% 假设）
- [x] 对比候选数据源的历史深度、分钟线、实时延迟、结算价、持仓量、调用限制及费用，选定一个主数据源。（akshare 新浪日线+60m；郑商所源不可用→排除）
- [x] 获取一个品种至少两个交割月份的样例，检查时间戳、交易日、成交量单位、缺失和重复记录。（rb2610/rb2701 等 5 合约；发现 60m 与日线成交量口径不可对账，量能判断只用日线）
- [x] 定义合约元数据：交易所、品种、合约、乘数、最小变动价位、上市/到期信息、交易时段和规则生效日期。（`data/futures_meta.py` 手维护表 + comm_info 在线交叉核验）
- [x] 明确保证金、手续费、涨跌停和交割限制的来源；历史回测缺少历史规则时，应标注近似口径。（P1 用期货公司快照；P2 用 futures_settle_* 逐日官方口径）
- [x] 记录主力选择与换月规则，保证在决策时点只使用当时已经可获得的数据。（已收盘日线成交量 argmax；连续序列仅研究用）

验收：能核对样例合约的 K 线、最小跳动盈亏及交易日归属，明确历史回测和实时监控各自的数据能力。数据不可用时先解决接入问题，不进入策略调参。✔（5 品种每跳盈亏与独立源全对；夜盘归属 cu/rb/hc 实证）

### P1：期货监控与风险测算 MVP

- [ ] 增加期货行情适配器，统一真实合约标识、时间戳、交易日、OHLCV、持仓量及可获得的结算字段。
- [ ] 实现增量更新、去重、缺口检查、重试与数据新鲜度检查；保留数据来源和更新时间。
- [ ] 根据交易所日历和品种时段区分交易中、休市和行情异常，正确处理夜盘与节假日。
- [ ] 观察池展示主力映射、真实合约、成交量、持仓量、临近到期和换月提醒。
- [ ] 接入一套 Donchian 趋势策略及 ATR 止损参考，只使用已完成 K 线。
- [ ] 明确信号含义：没有账户持仓时输出做多倾向、做空倾向或观望；有持仓上下文后才能生成开仓、平仓动作。
- [ ] 风险测算展示每手名义价值、每手保证金、止损距离、预估每手风险和可开手数，注明参数与价格时间。
- [ ] 对提醒设置持久化去重键，记录合约、周期、信号时间和策略版本，保证重启后不重复通知。

验收：完成观察池到通知的完整流程，连续 5 个交易日记录可追溯；行情过期、规则缺失或最小一手超过风险预算时，禁止生成可执行的开仓建议。尚未支持的期货回测入口应明确显示不可用。

### P2：可信的期货回测

- [ ] 扩展订单和持仓模型，区分方向、开平、平今/平昨、今仓/昨仓和成交状态。
- [ ] 实现期货账户账本：余额、权益、可用资金、持仓及冻结保证金、费用、已实现与未实现盈亏。
- [ ] 处理按结算价逐日盯市和成本重置，避免结算盈亏与平仓盈亏重复计入。
- [ ] 实现按手或按成交额收费，支持开仓、平今、平昨差异及规则按日期生效。
- [ ] 支持真实合约撮合、多空、最小手数和价位、滑点、成交量约束、涨跌停与部分成交。
- [ ] 使用真实合约计算成交与盈亏；连续序列仅用于明确口径的研究，换月显式记录平旧开新及成本。
- [ ] 模拟信号后下一可交易时点成交；同一根 K 线触发止盈止损等路径不明情况采用保守且可复现的规则。
- [ ] 加入保证金不足、保证金调整和临近到期处理；强平尝试仍受成交限制，不假定必然成交。
- [ ] 输出账户权益口径的收益、回撤、费用、交易次数、风险敞口、保证金占用和换月影响。
- [ ] 开展滚动样本外验证，保留最终未参与调参的数据，记录数据、参数和策略版本。

验收：多头、空头、平今/平昨、逐日结算、换月、保证金不足及无法成交等固定案例逐笔核对通过；能重现报告。策略收益另行评估，账务正确不代表策略有效。

### P3：实时模拟与策略评估

- [ ] 用实时行情驱动模拟账户，复用 P2 的账户和费用逻辑，明确模拟成交假设。
- [ ] 持久化信号、订单、成交、持仓和账户快照，建立每日对账及异常记录。
- [ ] 实现订单幂等、部分成交、撤单、拒单和重启恢复。
- [ ] 对照历史回放与实时模拟，解释信号时间、价格、费用和成交差异。
- [ ] 演练行情断开、行情过期、订单超时、重复事件、夜盘跨日和进程重启。
- [ ] 在观察开始前冻结策略版本及评估标准：最大可接受回撤、成本压力情景、交易样本要求和停止条件。
- [ ] 至少观察 4–8 周；低频策略交易样本不足时延长观察，并使用历史重放补充稀有事件验证。

验收：无未解释的账目差异和重复订单，异常能停止新增风险并恢复；策略在样本外及模拟阶段满足预先约定标准后，才评估实盘。不得通过临时更改指标让策略过关。

### P4：受控实盘

- [ ] 根据券商权限、平台兼容性及运维能力，在 vn.py/CTP、天勤 SDK 等候选方案中选择一个通道并验证当前支持范围。
- [ ] 完成认证、查询、报单、撤单、成交回报、断线重连与交易日切换。
- [ ] 启动及重连时以交易柜台查询结果对账；状态不确定时阻止新增订单，先查询再决定是否重试。
- [ ] 风控独立于策略执行，统一拦截人工、策略和重试产生的订单。
- [ ] 提供停止策略、禁止开仓、撤销未成交单及人工处置入口，明确各操作的范围。
- [ ] 编写部署、告警、日终核对、故障处置和回退到仅监控模式的操作文档。
- [ ] 根据单手风险和账户承受能力确定初始规模，满足限额才允许开仓。

验收：测试环境订单状态、重复报单防护、持仓对账和断线恢复通过，全部风险参数已明确配置，真实账户接入和启用另行确认。

## 5. 风控与仓位口径

止损风险估算：每手风险 = 止损价差 × 合约乘数 + 预估往返费用与滑点。

可开手数 = 向下取整 min（剩余交易风险预算 / 每手风险，可用于本次开仓的资金 / 每手所需保证金及费用）。

该计算是正常成交假设下的风险预算，不能保证跳空或封板情况下的最大亏损。还需独立校验：

- 单笔风险、账户总风险、同产业链集中度和总名义敞口。
- 保证金占用上限、资金缓冲及未成交订单冻结占用。
- 日内亏损、账户回撤及连续异常触发后的禁止开仓规则。
- 合约到期、个人账户交割限制、价格有效性与行情时效。

模拟阶段明确配置各限额，验证报警和拦截行为；实盘不得通过缺省配置自动放宽限额。

## 6. 代码实施边界

保留现有 Python、FastAPI、CLI、通知与存储基础，在现有模块边界内扩展。初期不引入微服务拆分。

| 现有位置（相对仓库根目录） | 计划改动 |
| --- | --- |
| `src/ripple_tradePilot/data/` | 期货行情适配、交易日历、合约元数据与版本 |
| `src/ripple_tradePilot/models/types.py` | 合约、方向、开平仓、订单状态和账户类型 |
| `src/ripple_tradePilot/strategies/`、`signals/` | 复用指标，加入期货信号及目标持仓语义 |
| `src/ripple_tradePilot/backtest/` | 独立期货规则、费用、账户结算及换月逻辑 |
| `src/ripple_tradePilot/risk/` | 按风险定仓、保证金及组合限额 |
| `src/ripple_tradePilot/execution/` | 实时模拟、交易通道、订单生命周期与对账 |
| `src/ripple_tradePilot/storage/` | 合约、信号、订单、成交、账户快照及迁移 |
| `src/ripple_tradePilot/api/`、`monitor/` | 期货工作流、运行状态与通知 |
| `tests/` | 期货账务固定案例、跨日规则、撮合与故障恢复测试 |

通用指标和展示能力共享；股票与期货的交易规则和账户核算分别实现。凡涉及公共接口的改动，需运行现有股票回归检查。
