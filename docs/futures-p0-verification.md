## 2. 数据源结论

| 接口（akshare 1.18.40） | 结果 | 用途 |
|---|---|---|
| `futures_zh_daily_sina(symbol)` | ✅ 真实合约日线：`date,open,high,low,close,volume,hold,settle`，**含持仓量与结算价**，覆盖全生命周期（rb2610 共 229 根，2025-10-16 起挂牌；数据新至 2026-09-18） | **主源**：日线、主力判定、持仓、新鲜度 |
| `futures_zh_minute_sina(symbol, period="60")` | ✅ 60 分钟线：`datetime,ohlc,volume,hold`，**历史深度约 8.5 个月**（1,023 根，2026-01-07 起）；夜盘 bar 齐全 | **主源**：60m 信号 K 线 |
| `futures_comm_info()` | ✅ 816 合约 × 21 列：现价/涨跌停板/每手保证金/开平今手续费/每跳毛利/主力标记，盘中更新（快照时间 2026-09-19 02:35，即周五夜盘收盘后） | 辅源：风险测算的保证金与费用快照、主力标记交叉核验 |
| `futures_settle_shfe(date)` | ✅ 逐日结算表：结算价 + 投机/套保 多空四向保证金率 + 手续费率 + 平今标志 | **P2** 逐日生效规则源；P1 不用 |
| `futures_contract_info_shfe()` | ✅ 276 合约：上市日/到期日/开始交割日/挂牌基准价 | 合约元数据（到期/临近到期提醒） |
| `futures_contract_info_dce()` | ❌ JSONDecodeError（接口返回异常） | 不用；DCE 到期日改由日线断流近似 + 品种规则推算 |
| `futures_zh_daily_sina` × 郑商所（TA609/TA701/MA609） | ❌ 空响应导致解析失败 | **郑商所暂不可用 → 首期范围排除**，依赖记录：待 akshare 修复或改用东财源后扩 |
| `futures_zh_realtime(symbol)` | ❌ KeyError | 单标的实时接口不可用；实时价格用 `futures_comm_info` 现价列替代 |
| `futures_display_main_sina()` | ✅ 品种→`{品种}0` 连续符号映射 | 仅确认命名；主力判定不用它（见 §5） |

**结论：主数据源 = akshare 新浪（日线 + 60m）**；免费、无 token、数据新至上一交易日。
两个已知缺陷（郑商所空响应、单标的实时不可用）都有替代或不影响首期范围。

## 3. 合约元数据与规则来源

- **乘数/最小变动**：手维护常量表（`data/futures_meta.py`，来源=交易所合约规则页），并以
  `futures_comm_info` 每跳毛利做在线交叉核验（P0 已人工核对 5 品种全对）。表带 `rule_version`。
- **保证金/手续费**：P1 用 `futures_comm_info` 快照（期货公司口径，显示时注明）；P2 回测需要
  逐日生效规则，改用 `futures_settle_shfe`（交易所官方、按日期），历史缺段标注近似口径。
- **涨跌停**：P1 直接用快照的涨停板/跌停板价格列（含交易所临时调整），不自算百分比。
- **到期日**：SHFE 用 `futures_contract_info_shfe`；DCE 该接口坏，用「品种到期月份惯例 +
  日线断流」近似并在 UI 标注近似值。

## 4. 交易日与夜盘口径（核验记录）

1. **bar 标签 = 结束时刻**：rb 日内 bar 标签 `10:00 / 11:15 / 14:15 / 15:00`（含 10:15–10:30
   小节休息的错位聚合），夜盘 `22:00 / 23:00`；cu 夜盘出现 `22/23/00/01` 四个小时 ✓（21:00–01:00）。
2. **夜盘归属下一交易日**：cu2610 出现标签 `2026-09-19 01:00`（周六凌晨，属周五夜盘）**和**
   `2026-09-21 00:00`（周一标签，同为周五夜盘）——新浪对跨零点 bar 的标签口径**不一致**
   （有时按自然日、有时按交易日）。因此适配器**不得信任标签日期**，统一规则：
   `hour ≥ 21 → 交易日 = 下一交易日(自然日)`；`hour < 4 → 交易日 = 该自然日起的下一交易日`；
   其余 → 自然日本身（应为交易日）。两种标签口径在该规则下都归到正确的交易日。
3. **成交量口径缺陷（重要）**：rb2610 周一(2026-09-14) 日线 volume=113,657，而 60m bar
   （周五 22:00 起 6 根）合计 81,382——两路聚合不同源，**无法逐笔对账**。处理：量能/持仓类
   判断只用日线 `volume/hold`；60m 只取 OHLC 与时间戳做信号。不以任何默认系数“修正”。
4. **交易日历**：无官方免费 API；用「主力品种日线日期集」作交易所日历（RB 229 个交易日），
   假期由断流自然体现。次日推算在日历未覆盖处退化为工作日近似并显式告警，不用静默默认值。

## 5. 主力映射与换月规则

- **主力判定**：每品种取最新**已收盘**交易日、全部在市合约中 `volume` 最大者（数据当时可得，
  无前视；hold 作并列参考）。与 `futures_comm_info` 的主力标记（rb2701 等 85 个）人工比对一致。
- **换月提醒**：主力判定发生切换的次日，或当前主力距到期 ≤ 20 个交易日时触发提醒。
- `futures_main_sina("RB0")` 连续序列**只用于研究口径**，监控与未来回测一律用真实合约（P2 验收项）。

## 7. 未解决问题与处理方式

| 问题 | 处理 |
|---|---|
| 郑商所新浪源空响应 | 首期排除 TA/MA 等郑商所品种；待 akshare 修复或接东财源后扩池 |
| 单标的实时行情接口不可用 | 用 comm_info 现价列（盘中更新）作盘中参考价；正式实时源 P3 再评估 |
| 60m 历史仅 ~8.5 个月 | 60m 策略预热/评估够用；P2 回测深度受限，长回测用日线口径单独跑 |
| DCE 合约表接口坏 | 到期日用品种惯例近似 + 标注；P2 若需要精确到期日再接 DCE 官网 |
| comm_info 保证金/手续费为某期货公司口径 | 展示时注明来源；实盘前以自家期货公司为准核对 |
| 60m 与日线成交量无法对账 | 量能/持仓判断只用日线（§4.3），不做静默修正 |

（5 品种与独立源全对）、夜盘归属（cu/rb/hc 实证）；历史回测与实时监控各自数据能力已在
§2/§4 区分。可以启动 P1。
